# Formal experiment index

Every formal experiment YAML in the release manifest is represented below. Training, evaluation, resource preparation and inherited base configurations are distinguished by role. Public quickstart and local runtime acceptance YAMLs are excluded.

- [CSV: exact configuration, encoder, training configuration and required resources](experiment-index.csv)
- [JSON: resolved inheritance, encoder registry and resource availability](experiment-index.json)
- [Encoder and resource catalog](models.md)

Commands are templates for the corresponding entrypoint, not a launch request. This indexing step performs no training or evaluation. Check each entrypoint's additional options for scenario protocols, repeated probe seeds and aggregation.

## Commands and preparation

For Physion, `command_sequence` includes feature extraction followed by both all-scenario and leave-one-scenario-out readouts. GRASP sequences include evaluation and property scoring. Kinematic rows record probe seeds 0–4 and their aggregation entrypoint; repeat the bank command with `--seed` for each recorded value before aggregation. Commands are not executed by this index.

Use `resource_ids` in JSON, or `required_resources` in CSV, to see the exact dataset, split, normalization/PCA, weight and optional source paths for a configuration. Only release-manifest resources are marked included; local acceptance links do not change that status. Training output directories and evaluation encoder input directories are checked during indexing; see the path consistency notes in [models.md](models.md).

## Regenerate the index

```bash
python scripts/build_experiment_index.py
```

The generator reads only release-manifest YAMLs and writes the four index documents. It does not import model weights or start jobs. After intentionally changing indexed files, refresh their release-manifest checksums before publication.
